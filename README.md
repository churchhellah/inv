# tinvest-agent

Агент для управления инвестициями через T-Invest API (Т-Инвестиции). Технические
индикаторы (SMA, RSI, MACD) считаются детерминированно, и по ним же детерминированная
стратегия (`decision/rules.py`) принимает решение buy/sell/hold — без обращения к каким-либо
платным внешним API. Финальный размер и допустимость любой сделки дополнительно проверяет
отдельный риск-менеджер по жёстким лимитам из `config/config.yaml` — стратегия не может их
обойти.

## Модель безопасности

- **Лимиты — только в конфиге.** `config/config.yaml` редактирует и коммитит человек; это
  единственный контур ручного управления рисками. Агент отказывается стартовать, если
  лимиты отсутствуют или некорректны.
- **`mode: sandbox`** по умолчанию — виртуальный счёт, реальные деньги не участвуют.
  Переключение на `mode: production` требует ТАКЖЕ `production_ack: true` — двойное явное
  подтверждение человека, чтобы нельзя было случайно включить боевой счёт одной строкой.
- **`trading_enabled: false`** — мгновенный killswitch: агент анализирует рынок и пишет
  решения в журнал, но никогда не отправляет заявки.
- **`dry_run: true`** — заявки не отправляются, даже если `trading_enabled: true` и
  `mode: production`. Используйте для обкатки стратегии и риск-менеджера перед реальными
  деньгами.
- **Whitelist инструментов** (`watchlist`) — агент торгует только перечисленными тикерами.
- **Полный аудит-лог** (`data/journal.db`, SQLite) — по каждому рассмотренному тикеру в
  каждом цикле: что предложила стратегия, что решил риск-менеджер и почему, что было
  исполнено. Смотрите через `tinvest-agent status` или напрямую через SQLite.

## Установка

Пакет T-Invest API SDK распространяется через собственный индекс T-Bank (не PyPI):

```bash
pip install t-tech-investments --index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple
pip install -e ".[dev]"
```

> Пространство имён импорта — `t_tech.invest` (НЕ `tinkoff.invest` — так было в старом,
> уже неактуальном пакете `tinkoff-investments`; они не взаимозаменяемы, весь код в
> `src/tinvest_agent/broker/` и `scripts/` уже написан под `t_tech.invest`).

## Настройка

1. Скопируйте `.env.example` в `.env` и заполните `TINVEST_TOKEN_SANDBOX` /
   `TINVEST_TOKEN_PROD`.
2. Для sandbox: создайте и профинансируйте sandbox-счёт —

   ```bash
   python scripts/sandbox_bootstrap.py 100000
   ```

   и пропишите выведенный `account_id` в `.env` как `TINVEST_ACCOUNT_ID_SANDBOX`.
3. Для боевого счёта: узнайте свой реальный `account_id` —

   ```bash
   python scripts/list_accounts.py
   ```

   (read-only, ничего не меняет) и пропишите нужный счёт в `.env` как
   `TINVEST_ACCOUNT_ID_PROD`. Sandbox и production используют разные переменные окружения
   для account_id специально — чтобы нельзя было случайно обратиться к боевому API с
   sandbox-счётом (и наоборот) при переключении `mode` в `config.yaml`.
4. Отредактируйте `config/config.yaml` — прежде всего `watchlist` и `limits`. Это шаг,
   которым человек аппрувит, чем и на сколько агенту разрешено торговать.
5. Прогоните тесты и ручной smoke-тест (см. «Верификация» ниже).

## Стратегия принятия решений

`decision/rules.py` — чисто детерминированная логика, без ML/LLM и без обращения к
сторонним платным API. Для каждого тикера из `watchlist` по последним свечам считаются три
независимых голоса:

- **Тренд**: SMA(10) выше/ниже SMA(30).
- **Momentum**: знак гистограммы MACD.
- **RSI**: не в перекупленности (для покупки) / экстремальная перекупленность (для продажи).

BUY требует минимум 2 согласованных бычьих голоса из 3 и перевеса над медвежьими. SELL
рассматривается только если позиция реально есть в портфеле, и требует минимум 2 медвежьих
голоса. При противоречивых или слабых сигналах — HOLD. Предложенная сумма сделки — не более
`limits.max_order_value_rub`; дальше её всё равно урезает риск-менеджер по кэшу, дневному
обороту и доле портфеля.

## Запуск

```bash
# Один проход анализа и (если разрешено конфигом) торговли
tinvest-agent run --once

# Непрерывная работа по расписанию из config.yaml (торговые часы MOEX учитываются)
tinvest-agent run --daemon

# Форсировать dry-run независимо от конфига — безопасно пробовать даже с trading_enabled: true
tinvest-agent run --once --dry-run

# Портфель, лимиты, использованный сегодня дневной оборот, последние записи журнала
tinvest-agent status
```

## Верификация

```bash
pytest
```

Юнит-тесты покрывают индикаторы (`tests/test_indicators.py`), стратегию
(`tests/test_rules.py`), риск-менеджер (`tests/test_risk_manager.py`, включая клампинг по
лимитам и whitelist) и схему решений (`tests/test_decision_schema.py`). Они не обращаются к
сети и не требуют токенов.

Для сквозной проверки брокерского слоя нужен реальный sandbox-токен и сеть:

```bash
python scripts/smoke_test_sandbox.py
```

Брокерский слой (`src/tinvest_agent/broker/`) обкатан против реального sandbox API
(резолвинг инструментов, портфель, котировки, свечи — все запросы отработали без ошибок).
Код соответствует тому, что реально установлено: `t-tech-investments` (не PyPI-пакет
`tinkoff-investments` — у него другое пространство имён импорта).

## Архитектура

```
src/tinvest_agent/
  config.py          # pydantic-конфиг + лимиты, загрузка config.yaml/.env
  broker/             # обёртка над T-Invest SDK: клиент, котировки, портфель, заявки
  analysis/            # технические индикаторы (SMA/EMA/RSI/MACD/Bollinger)
  decision/             # детерминированная стратегия (rules.py) + pydantic-схема решения
  risk/                  # риск-менеджер (клампинг лимитов) + SQLite-журнал аудита
  orchestrator.py          # один цикл: портфель -> индикаторы -> стратегия -> risk-check -> исполнение -> журнал
  scheduler.py              # APScheduler-демон, торговые часы MOEX
  cli.py                     # run --once|--daemon, status
```

Цикл анализа не хранит собственное состояние портфеля — источник истины всегда брокер,
кроме дневного оборота и истории решений, которые считаются из `data/journal.db`.
